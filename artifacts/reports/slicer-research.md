# Headless slicer research and real execution evidence

Date: 2026-07-31 UTC
Host: Ubuntu 22.04.5 LTS (Jammy), x86-64

## Decision

TopoForge now has independent OrcaSlicer and PrusaSlicer adapters. Discovery prefers
OrcaSlicer and falls back to PrusaSlicer. Both tested slicers lack a reliable
`--version` action in the builds exercised here, so the adapters probe `--help` and
then replace the provisional version with the authoritative `generated by ...`
G-code header after a successful slice.

The official OrcaSlicer 2.4.2 build targets Ubuntu 24.04 and does not run on this
Ubuntu 22.04 host. The last stable release with a generic Linux AppImage,
OrcaSlicer 2.3.0, does run through AppImage extraction mode and completed a real
slice. The Ubuntu PrusaSlicer 2.4.0 package also completed a real slice. No G-code
or AppImage is stored in the repository.

## Official CLI syntax verified from executable help

### OrcaSlicer

The official v2.3.0 AppImage reports:

```text
Usage: orca-slicer [ OPTIONS ] [ file.3mf/file.stl ... ]
--load-settings "setting1.json;setting2.json"
--load-filaments "filament1.json;filament2.json;..."
--slice option      Slice the plates: 0-all plates, i-plate i, others-invalid
--outputdir dir     Output directory for the exported files.
```

Canonical adapter invocation:

```bash
orca-slicer \
  --load-settings "PROCESS.json;MACHINE.json" \
  --load-filaments "FILAMENT.json" \
  --slice 0 \
  --outputdir OUTPUT_DIRECTORY \
  MODEL.stl
```

OrcaSlicer exposes an output directory, not an exact G-code filename. The adapter
slices in an isolated directory, verifies `result.json` and non-empty
`plate_1.gcode`, then atomically moves it to the caller's exact output path.

### PrusaSlicer

The installed Ubuntu binary reports:

```text
Usage: prusa-slicer [ ACTIONS ] [ TRANSFORM ] [ OPTIONS ] [ file.stl ... ]
--export-gcode, --gcode, -g
                     Slice the model and export toolpaths as G-code.
--load ABCD         Load configuration from the specified file.
--output ABCD, -o ABCD
                     The file where the output will be written.
```

Canonical adapter invocation:

```bash
prusa-slicer --export-gcode --output OUTPUT.gcode \
  [--load PROFILE.ini] MODEL.stl
```

The adapter points `--output` at a unique sibling file, verifies it, and
atomically publishes it at the caller's exact output path so an old G-code file
cannot be mistaken for a successful new slice.

## Real slicing results

Input for both runs: deterministic watertight 20 mm cube, 12 triangles,
`/tmp/topoforge-prusa-cube.stl` (1291 bytes).

### OrcaSlicer 2.3.0

Exact command:

```bash

  /tmp/OrcaSlicer_Linux_AppImage_V2.3.0.AppImage \
  --debug 2 \
  --datadir /tmp/topoforge-orca230-data \
  --load-settings "/tmp/orca230-extracted/squashfs-root/resources/profiles/Prusa/process/0.20mm Speed @MK3S 0.4.json;/tmp/orca230-extracted/squashfs-root/resources/profiles/Prusa/machine/Prusa MK3S 0.4 nozzle.json" \
  --load-filaments "/tmp/orca230-extracted/squashfs-root/resources/profiles/Prusa/filament/Prusa Generic PLA.json" \
  --slice 0 \
  --outputdir /tmp/topoforge-orca230-out \
  /tmp/topoforge-prusa-cube.stl
```

## Adapter behavior and limitations

- Discovery checks explicit paths, `TOPOFORGE_ORCA_SLICER` /
  `TOPOFORGE_PRUSA_SLICER`, then common PATH names.
- A real fallback probe marked the incompatible OrcaSlicer 2.4.2 AppImage `failed`
  for missing `GLIBC_2.38` and selected installed PrusaSlicer 2.4.0.
- `probe()` reports `available`, `unavailable`, or `failed` with executable,
  version, and a corrective detail.
- `slice()` reports `succeeded`, `failed`, or `unavailable`; failed processes do
  not publish stale or empty G-code.
- Parsed metrics cover estimated time, filament mm/cm3/g, layer count, actual or
  configured support, out-of-bed diagnostics, empty-layer warnings, floating
  region warnings, and literal warning lines.
- A slicer can only report warnings it detects. `false` warning flags mean the
  diagnostic stream did not contain those conditions; they are not an independent
  geometric proof.
- Filament mass is `0.00` in these default/generic runs because the selected
  configuration did not supply a usable filament density. Length and volume are
  therefore the useful measured material values.
