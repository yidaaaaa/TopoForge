# 本地安装、地图选区与离线使用

TopoForge 在本机运行，用浏览器选择区域、生成地形并下载模型。下面的安装命令面向已验证的 Linux x86_64 环境；地图浏览数据与用于打印的高程数据是两套独立数据。

## 安装与启动

准备 Git、Python 3.12 和 uv。首次安装需要联网，在希望保存项目的数据盘目录中运行：

```bash
git clone https://github.com/yidaaaaa/TopoForge.git
cd TopoForge
uv sync --locked
uv run --offline topoforge doctor
mkdir -p outputs/my-topoforge/inputs
```

已有仓库和安装环境时，进入原来的仓库目录即可。将自己的高程 GeoTIFF 放入 `outputs/my-topoforge/inputs`；如果它有同名 `.msk`、`.aux.xml` 或 `.ovr` 附属文件，一起保留。没有本地高程文件时，也可以联网通过地图选区获取。

```bash
uv run --offline topoforge web \
  --host 127.0.0.1 \
  --port 8765 \
  --state-dir outputs/my-topoforge/state \
  --workspace-root outputs/my-topoforge/workspaces \
  --input-root outputs/my-topoforge/inputs
```

打开 [本地 WebUI](http://127.0.0.1:8765/)，在页面顶部选择中文。`uv run --offline` 只限制 uv 的依赖下载，不会关闭应用里的地图或高程联网功能。若端口被占用，可以将 `8765` 换成空闲端口，并打开相应地址。

每次启动都从同一仓库目录运行同一命令，这样会继续使用已有任务与缓存。`state` 保存任务记录和地图、搜索缓存，`workspaces` 保存生成结果，`inputs` 是文件选择器可访问的输入目录；不要把这些目录当作安装临时文件删除。需要浏览其他文件夹时，增加一个 `--input-root /你的/数据目录`。

完成任务后，可在启动终端按 `Ctrl+C` 停止服务。关闭页面不会取消正在运行的构建；要取消任务，请先使用页面里的取消操作。重启恢复机制见 [Web 使用说明](web.md#job-recovery)。

## 找到地点、框选和导出

1. 打开“在线底图”，按需要选择“普通地图”或“地形地图”。地形底图用于观察山谷和山脊；构建后的“地形 / 高程 / 阴影”显示的是该任务实际处理的 DEM。
2. 在“查找地点”里开启“联网搜索”，输入地名或地址。中文地名可以写成 `西湖, 杭州`，核对结果的完整地址后再选择。也可直接输入 WGS84 的“经度, 纬度”，例如 `101.9, 31.1`。
3. 选中搜索结果只会移动地图。使用“绘制边界框”拖出打印范围，或点“以此为打印中心”并调整半径；左侧会显示对应的数据源和范围。已有高程文件时，选择“本地 DEM”并浏览文件。
4. 设置工作区名称、模型宽度和高度。首次可以保留“打印感知”和“自动适配”，暂不开启“执行软件切片”，然后点“开始构建”。地图选区的数据源在缺少高程缓存时会联网获取 DEM。
5. 任务完成后检查“三维模型”和拼装布局，再下载“通用 3MF（仅几何）”或 STL，导入切片器设置打印参数。只有配置了官方 Bambu Studio 并成功生成工程证据的任务，才会提供“Bambu Studio 工程 3MF（推荐打印）”。

同名地点可能位于其他城市，搜索结果也可能是镇而非山峰；确认地图位置后再框选。详情见 [地点搜索](web.md#find-a-place)与[首次构建](web.md#first-local-build)。

## 工作区、草稿与常用预设

顶部的“设置”和“结果”按钮可收起两侧面板，为地图和三维模型腾出空间；再次点击会恢复面板，填写中的参数保留。

“基础”模式集中显示数据源、模型尺寸和地形起伏。“高级”模式提供采样、资源上限、分片、连接器、覆盖物和软件切片。切回基础模式不会重置这些值；修改过的高级设置会在底部提示，生成时仍然生效。

表单改动会自动保存为草稿，刷新后恢复；已恢复的选区由本地引擎重新校验后显示。恢复草稿不会提交任务，也不会下载高程数据。草稿只保存在当前浏览器的同一访问地址，更换浏览器、端口或清理站点数据后不会自动转移。

打开“常用预设”，给当前模型设置起名并保存，下次选择后点“应用预设”。最多保存12个预设，只包含模型尺寸、采样、资源预算和拼装设置；地点、数据文件、工作区名称、覆盖物文件及软件切片选项保留当前值。删除预设不会改变正在编辑的表单。浏览器不允许保存时会显示提示，表单和构建仍可继续使用。

完成任务后，右侧顶部提供“三维模型”入口和主要模型下载；报告放在“更多文件与报告”，检查数据在“尺寸与检查详情”。备份和清理位于“备份与项目维护”，移除操作位于“任务管理”，恢复入口在“回收站与恢复”。这些折叠区可以随时展开。

## 断网前准备

| 想离线使用的内容 | 联网时要准备什么 |
| --- | --- |
| 道路、地名和地形底图 | 浏览目标区域和需要的缩放级别；地形背景需要切换到“地形地图”浏览 |
| 地点搜索 | 提交所需查询并选择、收藏地点；新地名不会自动拥有离线搜索数据 |
| 新的地形模型 | 准备覆盖目标区域的本地 DEM 及其附属文件；只看过地图还不够 |
| 已完成的模型、预览和下载 | 保留完整任务工作区和状态目录，重要任务另存备份 |

准备好后，开启“仅使用本地缓存”，断网刷新页面，并试一次本地 DEM 构建。该开关同时限制底图和地点搜索，不限制高程提供方联网；离线新建模型时选择“本地 DEM”最直接。已完成的任务可以离线查看，无需重新获取高程。

道路和地形缓存各最多保存 128 MiB、4096 块，只包含浏览器实际请求的区域和缩放级别，空间不足时会移除最久未使用的瓦片。它不是整包离线地图；缺失区域会提示未缓存。缓存保存在运行 TopoForge 的电脑上：如果通过远程端口转发访问，缓存就在远程主机，不在浏览器所在电脑。

收藏和最近地点保存在当前浏览器的站点数据里；更换端口、换浏览器或清理站点数据会影响这些列表。WGS84 坐标输入不需要搜索服务。完整说明见 [Web 地图缓存](web.md#terrain-basemap-before-building)与[高程离线工作流](offline-workflow.md)。

## 备份与恢复

选中已完成任务，展开“备份与项目维护”，点击“创建备份”，等待“备份已校验”后点击“下载备份”，将 ZIP 保存到独立位置。现有备份旁的“恢复副本”会创建一个新任务，不覆盖原工作区。

工作流备份包含该任务的结果和所需本地输入，但不包含通用的地图、搜索或高程提供方缓存，也不包含浏览器收藏。恢复到另一台电脑时，先安装 TopoForge，再使用 CLI 的 `restore` 命令；WebUI 没有上传任意备份 ZIP 的入口。具体命令见 [备份与恢复](offline-workflow.md#back-up-and-restore)。

需要移除任务时，可使用“将项目移入回收站”；误操作后在回收站“恢复批次”。永久清理后不能通过回收站恢复，重要任务应先下载备份。

## Windows 使用状态

目前已有 Windows x64 便携候选包及 Windows Server 托管 CI 验证。候选包内含 Python 和 `TopoForge-Web.cmd` 启动器，但尚未完成同一最终候选包在干净 Windows 10 22H2 x64、Windows 11 x64 上的双系统验收，因此还不是面向普通用户发布的 Windows 下载包。

后续验收需要在两套真实 Windows 客户端环境中分别验证启动、浏览器打开、构建、任务恢复和模型重开；官方 Bambu Studio 自动化另行验证。本页的 Linux 命令不表示 Windows 安装已获支持。准备参与候选包测试时，按 [Windows 验收说明](windows-support.md#clean-windows-client-evidence)使用同一个包和源码提交，不要将 Windows Server CI 当作 Windows 10/11 的结果。
