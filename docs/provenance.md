# Provenance

Each build writes source checksums; dataset provider/name/version/type; distinct source and processed horizontal resolution/grid shape; vertical CRS/datum or `unknown`; acquisition period; license/attribution; source URLs; original NoData and interpolation percentages; projection/resampling pipeline; horizontal scale; baseline; robust elevation range; vertical exaggeration; geometry method; output format writer; validation; and slicer evidence. For the default P2S target, provenance also records the official Bambu Studio asset/version/hash, flattened machine/process/filament preset hashes, resolved print parameters, normative-check result, G-code metrics, Bambu project 3MF hash, reopen/reslice result, and the release-gate decision.

`build_manifest.json` binds artifacts to SHA-256 values. `build_config.resolved.yaml` records all defaults and CLI overrides. `original_nodata_mask.tif` preserves the pre-interpolation mask. Dataset rights are not replaced by the Apache-2.0 code license.


Sampling/fidelity fields include `source_horizontal_resolution_m`, `processed_horizontal_resolution_m`, `source_grid_shape`, `processed_grid_shape`, `downsampling_factor`, `physical_sample_spacing_mm`, `estimated_triangle_count`, raw/processed elevation extrema, raw/processed peak coordinates, peak loss/shift and thresholds, `sampling_decision_reasons`, warnings, and `terrain_fidelity_status`. Published summit elevations are contextual comparisons only and always record whether any terrain adjustment was applied.

AOI provenance stores the exact user bbox or center-radius input, normalized WGS84 bounds/geometry, antimeridian status, selected local metric CRS, source pixel window, full/selected grid shape, pixel bounds, and full/partial coverage status. Orientation provenance and 3MF metadata store `east_axis`, `north_axis`, `north_edge`, `source_bounds`, and `orientation_transform`.

Network builds add `source_acquisition.json` as a checksummed bundle role. It records canonical request keys, authoritative catalog and tile URLs, dataset id, product-wide fallback decisions, ETag, Last-Modified, response bytes/status, content SHA-256, cache hit/miss/corrupt state, bounded network attempts, user and normalized AOI, source-footprint crop, licence URL, attribution, liability notice, and the SHA-256 of the acquired metric raster. The same object is embedded in `provenance.json`; the resolved config records the provider and acquisition-manifest path.


Copernicus AWS acquisitions also record an exact per-tile S3 object listing and an inventory for EDM (editing), FLM (ancillary filling), HEM (height-error standard deviation), and WBM (modified water) rasters. Every exposed source object retains URL, ETag, Last-Modified, byte count, content SHA-256, and cache status. A quality raster is published only when every selected DEM tile exposes the role and its source CRS, transform, width, and height align exactly with the corresponding DEM. Values are not remapped: the aligned AOI raster uses nearest-neighbour reprojection and the identical DEM coverage-crop window. Complete masks are copied into build bundles as `source_quality_edm`, `source_quality_flm`, `source_quality_hem`, and `source_quality_wbm` manifest roles; absent or incomplete roles remain explicit inventory decisions.
